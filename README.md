# Stitches & Stories — frontend

React + TypeScript + Vite. Разработка ведётся в ветке `develop`.

Бэкенд: [stitches-stories-backend](https://github.com/aleksr777/stitches-stories-backend/tree/develop).
Основа — `aleksr777/react-routing-authorization`; происхождение зафиксировано в [SOURCE-TEMPLATE.md](SOURCE-TEMPLATE.md).

## Журнал мастерской

`/journal` — лента одобренных публикаций из VK. Переход доступен в главном меню. Администратор открывает **«Публикации из VK»** в профиле или по адресу `/admin/journal`, сохраняет страницу и получает новые посты в очередь. Для публикации каждой записи требуется отдельное одобрение; доступны отклонение, снятие с сайта и обновление копии из VK с повторной проверкой.

Переносятся текст и фотографии; видео и другие вложения открываются по ссылке на оригинал. Фото отображаются целиком. Неодобренные записи и фотографии защищены на сервере. Встраиваемых VK-виджетов нет.

Токен VK настраивается только в `.env` бэкенда, переменная `VK_ACCESS_TOKEN`. [Инструкция подключения и ограничения](https://github.com/aleksr777/stitches-stories-backend/blob/develop/docs/VK-JOURNAL.md). Для обновления существующего сервера выполните новую миграцию перед запуском. Без токена магазин работает, а кнопка импорта в кабинете недоступна.

## Что реализовано

- Главная в стиле согласованных макетов: молочный фон, пудровые акценты, Cormorant Garamond и Manrope. Шрифты хранятся локально.
- Каталог, поиск, категории, сортировка по цене, карточка изделия, корзина и предварительная заявка без обязательной регистрации.
- Адаптивная сетка для ширины от 320 px до 4K с ограничением ширины контента. На маленьких телефонах карточки идут в одну колонку.
- Модальные вход, регистрация с подтверждением почты и восстановление пароля. После входа — круглая аватарка со ссылкой в кабинет.
- Кабинет: заявки, избранное, изменения профиля/пароля/почты, управление сеансами, история и отзыв согласий.
- Отдельные подтверждения документов; добровольная подписка с подтверждением почты; аналитика не подключена.
- Раздел владельца `/admin/shop`: карточки товаров и статусы заявок. Доступ ограничивается также на сервере.

## Запуск

Сначала запустите бэкенд по его README. Затем:

```bash
git switch develop
npm ci
cp .env.example .env
npm run dev -- --host 127.0.0.1
```

В `.env` для локальной разработки:

```dotenv
VITE_API_URL=http://localhost:5174/api
VITE_BASE_PATH=/
```

Открыть `http://localhost:5173`. Логин владельца и пароль задаются через `INITIAL_ADMIN_*` в локальном `.env` бэкенда. Тестовые письма находятся в Mailpit: `http://127.0.0.1:18025` по умолчанию; порт задаётся через `MAILPIT_WEB_PORT` в бэкенде. Запуск сервисов и устранение конфликтов портов описаны в [README бэкенда](https://github.com/aleksr777/stitches-stories-backend/tree/develop#запуск-для-разработки).

```bash
npm run typecheck
npm run lint
npm run stylelint
npm run prettier
npm test
VITE_API_URL=http://localhost:5174/api npm run build
```

CI проверяет ветки `develop` и `main`; push в `develop` не публикует сайт. Унаследованный workflow публикации Pages относится к `main` и требует явного адреса API. Для рабочего магазина размещение и обработка данных в РФ выбираются отдельно.

## Структура

- `src/store` — витрина, корзина, заявки, кабинет, документы и раздел владельца.
- `src/features/auth` и `src/shared/api` — авторизация и клиент API из исходного шаблона.
- `src/pages/account-settings` — настройки аккаунта.
- `public/fonts` — шрифты и лицензии OFL.
- `public/images` — оригинальные фотографии изделий. Размещайте здесь файлы и указывайте пути `/images/имя.jpg` в карточке товара. Автоматическая загрузка фотографий через админку пока не реализована.
- `test/store-flows.test.jsx` — сценарии рабочего магазина с подменённым API.
- `test/template-app.jsx` — отдельная оболочка для сохранённых регрессионных тестов авторизации шаблона. Она не включается в рабочее приложение.

## Текущий этап

Это первая версия для разработки, без приёма платежей. Заявка сохраняется на сервере; наличие, доставка и оплата согласуются с мастером. Она не резервирует складской остаток и не является оплаченным заказом.

Цены и изделия в демо — примеры. Исходные фотографии не заменялись вымышленными работами. Юридические тексты передаются API и отмечаются как проекты до заполнения реквизитов и параметров реальных сервисов.

Access token хранится только в памяти, refresh token — в HttpOnly cookie. В localStorage записываются только идентификаторы изделий и количество в корзине. Личные данные формы заявки и пароли туда не записываются.

Автоматические тесты проверяют поведение компонентов. Визуальная проверка в реальном браузере на всех контрольных ширинах (320, 390, 768, 1440, 1920, 3840 px) остаётся отдельным этапом: браузер текущей среды блокирует локальный адрес.
