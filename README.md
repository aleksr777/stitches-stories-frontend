# Stitches & Stories — frontend

React + TypeScript + Vite. Разработка ведётся в ветке `develop`.

Бэкенд: [stitches-stories-backend](https://github.com/aleksr777/stitches-stories-backend/tree/develop).
Основа — `aleksr777/react-routing-authorization`; происхождение зафиксировано в [SOURCE-TEMPLATE.md](SOURCE-TEMPLATE.md).

## Что реализовано

- Главная в стиле согласованных макетов: молочный фон, пудровые акценты, Cormorant Garamond и Manrope. Шрифты хранятся локально.
- Каталог, поиск, категории, сортировка по цене, карточка изделия, корзина и предварительная заявка без обязательной регистрации.
- Адаптивная сетка для ширины от 320 px до 4K с ограничением ширины контента. На маленьких телефонах карточки идут в одну колонку.
- Модальные вход, регистрация с подтверждением почты и восстановление пароля. Владелец дополнительно подтверждает вход шестизначным кодом из письма; после входа появляется круглая аватарка со ссылкой в кабинет.
- После входа посетитель возвращается на страницу, с которой открыл окно; после завершения или отзыва сеанса — на главную без повторного открытия окна авторизации.
- Кабинет: заявки, избранное, изменения профиля/пароля/почты, управление сеансами, история и отзыв согласий. Закрытие кабинета подтверждается текущим паролем.
- Отдельные подтверждения документов; добровольная подписка с подтверждением почты; аналитика не подключена.
- Раздел владельца `/admin/shop`: создание, редактирование и безопасное удаление карточек товаров с подтверждением, а также статусы заявок. В «Пользователях» владелец просматривает сеансы, блокирует или разблокирует покупателей, а удаление учётной записи подтверждает своим текущим паролем. Доступ ограничивается также на сервере.
- Загрузка фотографий с компьютера при создании и редактировании изделия, предпросмотр, выбор основного фото и удаление. Каталог, карточка и корзина получают сохранённые изображения с сервера; в карточке можно переключать фотографии.

## Запуск

Сначала запустите бэкенд по его README. Затем:

```bash
git switch develop
npm ci
cp .env.example .env
npm run dev -- --host 127.0.0.1
```

В `.env` для локальной разработки:

```dotenv
VITE_API_URL=http://localhost:5174/api
VITE_BASE_PATH=/
```

Открыть `http://localhost:5173`. Логин владельца и пароль задаются через `INITIAL_ADMIN_*` в локальном `.env` бэкенда; после них потребуется код из письма. Тестовые письма находятся в Mailpit: `http://127.0.0.1:18025` по умолчанию; порт задаётся через `MAILPIT_WEB_PORT` в бэкенде. Запуск сервисов и устранение конфликтов портов описаны в [README бэкенда](https://github.com/aleksr777/stitches-stories-backend/tree/develop#запуск-для-разработки).

```bash
npm run typecheck
npm run lint
npm run stylelint
npm run prettier
npm test
VITE_API_URL=http://localhost:5174/api npm run build
```

CI проверяет ветки `develop` и `main`; push в `develop` не публикует сайт. Унаследованный workflow публикации Pages относится к `main` и требует явного адреса API. Для рабочего магазина размещение и обработка данных в РФ выбираются отдельно.

## Структура

- `src/store` — витрина, корзина, заявки, кабинет, документы и раздел владельца.
- `src/features/auth` и `src/shared/api` — авторизация и клиент API из исходного шаблона.
- `src/pages/account-settings` — настройки аккаунта.
- `public/fonts` — шрифты и лицензии OFL.
- `public/images` — прежние статические фотографии: сохранённые пути `/images/имя.jpg` продолжают работать. Новые фотографии загружаются из админки в API и хранятся в PostgreSQL.
- `test/store-flows.test.jsx` — сценарии рабочего магазина с подменённым API.
- `test/product-images.test.jsx` — создание и редактирование с фотографиями через настоящий App, повтор после ошибки, предпросмотр и галерея.
- `test/template-app.jsx` — отдельная оболочка для сохранённых регрессионных тестов авторизации шаблона. Она не включается в рабочее приложение.

## Текущий этап

Чтобы добавить фотографии, откройте «Управление магазином» → «Новое изделие» (либо «Изменить») → «Добавить фотографии». Для нового изделия обязательны только название, цена больше 0 ₽ и хотя бы одна фотография; адрес в каталоге создаётся автоматически, остальные поля уже имеют безопасные значения по умолчанию. Выберите до 8 файлов JPEG, PNG или WebP, до 8 МБ каждый и 40 мегапикселей. Первое фото используется в каталоге; кнопка «Сделать основным» меняет его. Файлы отправляются вместе с карточкой по кнопке «Сохранить изделие». При ошибке форма и выбранные файлы сохраняются для повторной попытки; закрытие окна отменяет несохранённые изменения. Изображения скрытого изделия видны в форме администратору. Для показа покупателям включите «Показывать в каталоге»; в production также снимите «Демонстрационный товар». Если опубликованных изделий ещё нет, витрина вместо карточек показывает посетителю спокойное сообщение о готовящейся коллекции.

Перед использованием обновите бэкенд, установите его зависимости (`npm ci`), примените миграции (`npm run migration:run`) и перезапустите API. Адреса фотографий формируются из `VITE_API_URL`; политика CSP разрешает изображения только с адреса API, самого сайта и локальные предпросмотры `blob:`/`data:`. Если хостинг добавляет отдельный CSP-заголовок, разрешите в его `img-src` адрес API и `blob:`.

Заявка сохраняется на сервере; наличие, доставка и сроки согласуются с мастером. Сама заявка не резервирует складской остаток и не является оплаченным заказом. После согласования владелец может выставить отдельный счёт СБП: «Управление магазином» → заявка со статусом «Согласована» → «Подготовить оплату СБП». Покупателю передаётся приватная ссылка, а вошедший покупатель видит счёт в профиле. Страница показывает итоговую сумму, продавца, условия и статус, подтверждённый сервером. Владелец не может оплачивать и не подписывает покупательские документы.

Для СБП сначала обновите и мигрируйте бэкенд. Настройки Robokassa хранятся только на сервере: [инструкция подключения и смены продавца](https://github.com/aleksr777/stitches-stories-backend/blob/develop/docs/SBP.md). При отдельном CSP-заголовке хостинга добавьте `https://auth.robokassa.ru` в `form-action`. По умолчанию оплата отключена. Тестовый режим обозначен в интерфейсе и не списывает деньги; реальная работа требует подключения кабинета и проверки чека НПД. Ссылка гостевого счёта содержит секрет во фрагменте `#token=…`, не сохраняется в browser storage и должна передаваться только покупателю.

Цены и изделия в демо — примеры. Исходные фотографии не заменялись вымышленными работами. Юридические тексты передаются API и отмечаются как проекты до заполнения реквизитов и параметров реальных сервисов.

Access token хранится только в памяти, refresh token — в HttpOnly cookie. В localStorage записываются только идентификаторы изделий и количество в корзине. Личные данные формы заявки и пароли туда не записываются.

Автоматические тесты проверяют поведение компонентов. Визуальная проверка в реальном браузере на всех контрольных ширинах (320, 390, 768, 1440, 1920, 3840 px) остаётся отдельным этапом: браузер текущей среды блокирует локальный адрес.
